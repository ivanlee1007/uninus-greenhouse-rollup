## 可獨立操作的最小路徑

使用已設定的 Cover ID，而不是直接對原始方向 Switch 下命令：

```yaml
action: cover.set_cover_position
target:
  entity_id: cover.east_rollup
data:
  position: 35
```

`35` 為標準開啟百分比，不是覆蓋百分比。未知位置只接受端點 `0`／`100` 完整校正；中間目標拒絕時不取消既有端點保護計時。

停止使用原生 `cover.stop_cover`。硬體參數可從 Integration「設定／重新設定」、所屬裝置的四個原生 Number 或 `apply_parameters` 服務修改；三者共用同一權威。數值更新僅限閒置且兩路實際來源均回報 OFF，不能用參數儲存來停止或啟動馬達。

## 離線驗證項目

| 邊界 | 永久測試 |
|---|---|
| 原生服務可獨立指定開度、關閉兩路、STOP 後新 Core 還原位置但不續跑目標 | `test_parameters_native.py` 的 standalone/new-Core 測試 |
| 開啟、關閉不同時間預算，原動作停止後再算剩餘預算 | `test_target_position.py` |
| 不明位置、延遲回報、反向、按停止、卸載、來源失聯、停止失敗 | `test_target_position.py` |
| 目標計時到達仍等待雙路 OFF，ACK 不冒充 OFF，逾時回報 error | `test_target_position.py` 的 stop-feedback 測試 |
| 不可用狀態的原生磁碟位置保存與還原、損壞資料拒絕 | `test_cover_restore.py` |
| 行程時間改變後不恢復舊校正，新模型快照不被過期種子覆蓋 | `test_cover_restore.py` |
| Options／重新設定／Number／服務共用權威、授權、併發、寫入失敗、卸載與重啟 | `test_parameters_native.py` |

## 單台實機驗收（尚未執行）

以下項目須先由使用者指定測試機並明確授權操作與必要的 HA 重啟。保存原始設定／版本、四個硬體參數、Cover 位置與兩路輸出狀態；停用會競爭相同輸出的舊 Automation，確認硬體互鎖、限位、獨立最大通電保護與人工急停可用。不可在無急停能力下刻意模擬卡住／斷線。

- [ ] 檢查綁定的是實際輸出回報，不把虛擬計時序列視為實際輸出。
- [ ] 未校正時拒絕中間開度，既有端點計時仍有效；完整校正後可指定中間開度。
- [ ] 執行一次中間開度，驗證計時與雙路 OFF 回報；到時不等於已量測實體到位。
- [ ] 途中按停止、再指定不同方向，確認舊計時不能停掉或重新啟動新動作。
- [ ] 運轉中參數編輯被拒絕；閒置數值修改從原生設定與 Number 均能保存、重開一致，且不啟停輸出。
- [ ] 修改全開／全關秒數使舊校正失效；重新校正後新位置可恢復。
- [ ] 經授權正常重啟 HA，位置還原但不恢復舊目標；來源未恢復時維持 unavailable。
- [ ] 使用安全測試條件確認延遲／缺失 OFF 回報不會假裝成功，並記錄實際輸出及診斷。
- [ ] 保存測試結果並清理本次暫時設定與測試操作；確認所有輸出回到授權的安全狀態。

時間估算無法取代實體位置回授，也不承諾斷電最後一刻保存或網路失聯時仍能由 HA 斷電。
